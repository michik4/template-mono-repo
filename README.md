# Modern Fullstack Monorepo Template

> Документация написана ИИ, т. к. впадлу было писать руками

Современный шаблон монорепозитория, спроектированный для создания масштабируемых Fullstack-приложений с разделением клиентов (desktop/mobile) и переиспользуемой бизнес-логикой.

## 🛠 Технологический стек

- **Пакетный менеджер:** [Bun](https://bun.sh/)
- **Оркестрация:** [Turborepo](https://turbo.build/)
- **Backend:** [NestJS](https://nestjs.com/)
- **Frontend:** [Next.js](https://nextjs.org/) (с включенным React Compiler)
- **База данных:** PostgreSQL + [Drizzle ORM](https://orm.drizzle.team/)
- **Валидация конфигурации:** Zod
- **Линтинг и форматирование:** ESLint (Flat Config), Prettier, кастомный AST-линтер на базе `ts-morph`

## 📦 Структура проекта

Репозиторий разделен на приложения (`apps/`) и переиспользуемые пакеты (`packages/`):

### Приложения (`apps/`)
- `backend` — API на NestJS.
- `web-desktop` — Десктопная версия веб-клиента на Next.js.
- `web-mobile` — Мобильная версия веб-клиента на Next.js.

### Пакеты (`packages/`)
- `config` — Строго типизированные конфигурации окружения (Backend, Client, DB) на базе Zod.
- `db` — Единый источник истины для работы с базой данных (схемы Drizzle ORM, миграции, универсальный Generic-репозиторий).
- `shared` — Разделяемые типы (DTO) и наша **кастомная система линтинга**.
- `ui` — Общие компоненты, стили и дизайн-система.

### Инструменты разработки (`.dev/`)
- `scripts/init.*` — Скрипты быстрой установки Node.js (fnm) и Bun для новых разработчиков (Win/Mac/Linux).
- `scripts/setup-template.ts` — Утилита для переименования шаблона под ваш проект.
- `scripts/snapshot.ts` — 🤖 **Уникальная фича:** Генератор Markdown-снапшотов исходного кода. Позволяет мгновенно собрать контекст по нужным пакетам для передачи в ChatGPT/Claude/Cursor.

## 🚀 Быстрый старт

### 1. Настройка нового проекта
После клонирования репозитория кастомизируйте его под свой проект (заменит `@repo` на ваш скоуп и имя проекта):
```bash
bun .dev/scripts/setup-template.ts --scope @myorg --name my-project
```

### 2. Подготовка окружения
Если у вас еще не установлены необходимые версии Node и Bun, выполните скрипт инициализации:
- **Mac / Linux:** `source .dev/scripts/init.sh`
- **Windows:** `.\.dev\scripts\init.ps1`

### 3. Установка зависимостей
```bash
bun install
```

### 4. Настройка переменных окружения
Создайте `.env.backend` и `.env.db` в корне проекта (смотрите требуемые поля в пакете `packages/config`).

### 5. Запуск разработки
Сборка и запуск всех приложений параллельно с помощью Turborepo:
```bash
bun run dev
```

## 🧠 Интеграция с LLM (Snapshots)
Шаблон включает мощный инструмент для работы с нейросетями. Если вам нужно передать контекст проекта или его части в LLM, используйте:
```bash
# Сделать снапшот всего проекта
bun run snapshot:code --global --out all.md

# Сделать снапшот только бекенда и БД (с минификацией отступов)
bun run snapshot:code -- backend packages/db -m
```
Файлы будут сохранены в папку `.dev/code_snapshots/`.

## 🛡 Кастомный линтинг (Custom AST Rules)
В пакете `@repo/shared/lint` реализован конвейер статического анализа на базе `ts-morph`. По умолчанию он содержит правило `RouteConflictLinter`, которое предотвращает баги маршрутизации в NestJS, когда статические роуты перекрываются Wildcard-роутами (например, `@Get(':id')` находится ниже `@Get('me')`).

Запуск проверки:
```bash
bun run lint
```
